# 009 — 同名工具的子进程被误判为 shim 递归

## 原因与复现

旧 shim 启动工具前设置 `OSDK_SHIM_ACTIVE=<工具名>`，下次看到同名标记就返回 126。
这个标记会被真实工具及其子进程继承。因此 Node 服务、IDE 或构建任务里的正常
`/usr/bin/env node` 调用，只要 PATH 再命中 shim，也会被拒绝。守护进程会长期保留
这个标记；只改项目配置或重试调用不能恢复。

隔离测试建立两个项目，各选一个 Node 版本，让第一个项目的真实工具通过 shim
启动第二个项目的工具。修复前，继承同名标记、跨项目子进程两项测试均以 126 失败。
005 中按工具名比较的修复仅解决了不同工具间的调用，没有覆盖这个场景。

## 修复与验证

递归判定改到目标解析之后，复用 system 目标已有的 osdk 身份检查：同文件、二进制
副本、生成的包装脚本不能成为实际执行目标。正常工具可继续通过 shim 调用同名工具，
按子进程所在项目重新选择版本。启动目标时移除旧标记，兼容仍携带标记的长驻父进程，
也避免把它传给旧版 shim。

回归覆盖同名旧标记、两个项目与两个版本、真实子进程、标记清理，以及硬链接和副本
指回 dispatcher 的情况。自引用测试带执行上限；移除目标检查后必须失败，不能挂住测试。

Linux 完整工作区测试通过 2189 项，另有 5 项既有忽略；格式检查和 Clippy 的
`-D warnings` 门禁通过。交互基准修复前后均发现 8 个动态安装，装置都是 355 个目录、
522 个条目，其中 232 个目录属于安装负载，静态子树诱饵检查通过。扫描耗时仅供参考：
fail-closed 由 0.53 ms/次变为 0.42 ms/次，tolerant 由 0.79 ms/次变为 0.42 ms/次。
